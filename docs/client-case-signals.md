# Сигналы заявок клиентов

Верхний счётчик и список просроченных заявок строятся по текущим делам активного филиала с теми же сроками, что в упрощённой CRM. Отсутствие персонального журнала доставки не скрывает просроченную заявку. Сбой сети сохраняет последние успешно загруженные счётчики.

Звуковые сигналы обязательны и включены по умолчанию. В интерфейсе нет переключателя отключения звука; старые сохранённые значения «выключено» игнорируются. Приложение сразу пробует запуск аудио, а если браузер блокирует автозвук — любой обычный клик, касание или нажатие клавиши возобновляет аудио без отдельной кнопки. Новые заявки, пришедшие до разрешения звука браузером, сохраняются в очереди и озвучиваются после активации. Просрочка, уже снятая к этому моменту, не озвучивается. Системные уведомления разрешаются отдельным действием в профиле; отказ от них не выключает звук.

Для голосовых записей подготовлен `public/audio/client-case-signals.json`: поля `new` и `overdue` принимают пути к локальным MP3, WAV, OGG или M4A внутри `/audio/`. Подключены записи пользователя: `client-case-replica-1.mp3` — новое дело, `client-case-replica-2.mp3` — просроченное дело. Они воспроизводятся через тот же AudioContext; две фразы ставятся последовательно и не накладываются друг на друга. При недоступности записи используется встроенный сигнал.

Открытые вкладки проверяют заявки каждые 30 секунд, включая фоновые. Начальный ответ устанавливает серверное время отсчёта: существующие заявки не объявляются новыми. Дальше новые заявки сопровождаются голосовой записью о новом деле. Пока есть просроченная заявка, для которой не действует отсрочка, голосовая запись о просроченном деле повторяется раз в 5 минут. Закрытие или изменение статуса, снимающее просрочку, прекращает повтор. Несколько вкладок одного браузера используют Web Locks и локальные метки доставки, чтобы не дублировать звук; другие устройства получают собственные сигналы. Доставка не зависит от глобального подтверждения уведомления сотрудником на другом устройстве.

Системные уведомления используют отдельный service worker без кеширования и перехвата запросов. Это уведомления от открытых вкладок, а не серверный Web Push: закрытые/замороженные вкладки и спящие устройства не обеспечивают фоновую доставку. Ограничения браузера, энергосбережение и запрет уведомлений ОС могут задерживать или блокировать звук и системные уведомления.

Проверки: `npm run test:client-cases`, `node scripts/test-client-case-alert-route.mjs`, `node scripts/test-navigation-ia.mjs`, `node scripts/test-background-load-guards.mjs`, `node scripts/test-branch-production-guards.mjs`, TypeScript. Тесты не отправляют реальные уведомления и не обращаются к рабочей базе.

В просрочку также входят поставки в статусе «Запчасти заказаны» с истёкшим `suppliesExpectedAt`. Старый срок расчёта в этом статусе не используется. Ссылка «Просроченные» открывает все просроченные колонки, включая поставки, на настольном и мобильном экранах.

Закрытие кассовой смены проверяет текущие сроки всех активных дел того же филиала на сервере. При просрочке API возвращает `409 OVERDUE_CLIENT_CASES` с количеством дел и оставляет кассу открытой, в том числе для владельца. Отсрочка уведомления не снимает просрочку для закрытия кассы. Закрытые дела и дела других филиалов не блокируют смену; ошибка проверки CRM также не разрешает закрытие. Проверка: `npm run test:cash-shift-policy`.

При попытке закрыть кассу ответ `409` содержит `overdueCases`: все блокирующие дела активного филиала, в том числе с отложенным уведомлением, от старых сроков к новым. Касса показывает название, клиента, действие и срок каждого дела со ссылкой `/crm?dealId=…` в новой вкладке, чтобы сохранить введённые суммы. При повторной попытке сервер заново проверяет просрочку.
