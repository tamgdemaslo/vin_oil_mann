# Программа лояльности CRM

Гагарина и Дачная используют одну PostgreSQL. Счёт принадлежит бизнес-группе, а карточки, отгрузки и просмотр истории ограничены активным филиалом. Проведение и возврат в черновик проходят через `src/lib/local-demand-write.ts`. В той же транзакции фиксируются расчёт, складское движение и бонусные операции. AQSI получает денежные суммы из расчёта проведённой отгрузки. Повторная отправка использует сохранённый запрос на кассу.

## Включение и работа

- Владелец открывает **Управление → Программа лояльности**, включает программу и сохраняет правила. Для отдельных ставок выбирает товарную группу соответствующего филиала, например «Масла» со ставкой 3% и «Фильтры» со ставкой 7%. Явная ставка 0% действует на начисление. Исторические продажи не начисляют бонусы.
- В отгрузке мастер выбирает персональную карточку. При предложении привязки мастер сверяет счёт со слов клиента. Для списания мастер нажимает **Списать бонусы**, проверяет денежную сумму и проводит отгрузку. После смены клиента списание сбрасывается. Спорные карточки управляющий разбирает на странице программы.
- В карточке клиента владелец может сделать корректировку с причиной. Мастер начисляет компенсацию из проведённой отгрузки этого клиента.
- В **Кого вернуть сегодня → Начислить бонусы за акцию** владелец выбирает аудиторию, сумму, срок и основание. После предпросмотра подтверждает начисление. Обработку можно продолжить из недавних акций. Встроенные бонусные рассылки пока не имеют доступного канала CRM.
- В проведённой отгрузке управляющий сверяет частичный возврат по позициям и регистрирует реквизиты оформленного возвратного чека. Если цены маркированных упаковок в исходном чеке различаются на копейку, управляющий выбирает коды возвращаемых упаковок. Форма фиксирует кассовый возврат в бонусном журнале и сводке продаж. Оформление самого чека и складское оприходование выполняются отдельно.

## Проверки

`npm run test:customer-loyalty` проверяет расчёт, округление, срок, возвраты по количеству, цены AQSI и роли. `npm run test:customer-loyalty-api` запускает HTTP-сценарии с тестовыми аккаунтами, CRM на loopback и отдельной PostgreSQL `eco_loyalty_api_test`. Скрипт поднимает локальный имитатор AQSI. Его параметры и роли зафиксированы в тесте. Для локального запуска из рабочего checkout задайте `CASHBOX_DISABLE_LEGACY_IMPORT=1`, чтобы CRM использовала только кассовые данные тестовой БД.

Миграция `20261123090000_customer_loyalty` применяется отдельно после согласования и проверки резервной копии Timeweb. Для приёмки на кассе нужно сверить итог фискального чека с предчеком CRM, включая маркированные упаковки, дробное количество и возврат. Дробная позиция передаётся в AQSI с точностью цены, необходимой для воспроизведения итоговой суммы строки.
