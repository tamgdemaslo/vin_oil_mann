# Отдельный учёт бочек разливного масла

Товар остаётся одной карточкой с общей ценой и суммарным складским остатком.
Физические бочки хранятся отдельно, с кодом DataMatrix, внутренним номером,
складом, принятым объёмом, остатком и историей действий.

## Работа сотрудника

1. Для существующего разливного товара откройте «Маркировка → Бочки на складе».
   При необходимости выберите склад текущей бочки и включите отдельный учёт.
   Текущие код и остаток переносятся без добавления литров на склад.
2. В приёмке добавьте разливной товар. Укажите объём и отсканируйте код каждой
   бочки. Количество позиции — сумма литров; закупочная цена — за литр.
   Черновик сохраняет сканы, проведение создаёт запечатанные бочки.
3. При подключении новой бочки откройте её товар и используйте «Сменить бочку».
   Выберите принятую бочку или повторно отсканируйте её DataMatrix.
4. Если старая физически пустая, а в учёте ещё есть литры, подтвердите это и
   укажите причину. Создаётся отдельное фактическое списание с расходом в
   управленческом учёте. При нулевом остатке списание не создаётся.
5. Последующие продажи берут код и списывают литры из подключённой бочки.
   Сканирование каждой продажи не требуется. Переключение при недостатке
   остатка не происходит автоматически. Одна позиция продажи не распределяется
   между двумя бочками: отпуск из старой нужно оформить до её закрытия.

Одна активная бочка на товар в филиале. При продаже склад отгрузки должен
совпадать со складом активной бочки. Остатки запечатанных бочек видны в общем
складском остатке, но для продажи из них необходимо явно начать разлив.

## Сохранность учёта

- Повторный код в приёмке отклоняется, включая уже закрытые бочки.
- Приёмку использованной бочки нельзя отменить. Отмена приёмки запечатанной
  бочки отменяет её запись; повторное проведение той же приёмки сохраняет ID.
- Код и остаток управляемой бочки защищены от прямой правки карточки. Открытая
  ранее карточка не может затереть остаток после продажи.
- Копирование карточки между филиалами не переносит физическую бочку и её код.
- Списание бочки и сохранение задания в очереди AQSI выполняются одной
  транзакцией. Повторная отправка сохраняет первоначальный код и не списывает
  литры повторно. Пока AQSI недоступна, литры уже закреплены за принятым заданием.
- История бочки и существующий аудит маркировки сохраняются вместе с изменением.

## Включение на рабочем сайте

Подготовлена миграция `20260929120000_bulk_oil_barrels`: две новые таблицы,
филиальные внешние ключи, уникальность кода и одной активной бочки, ограничения
объёма. Она не изменяет имеющиеся товары или складские остатки. Текущие бочки
переносятся при включении учёта или первой новой приёмке. При остатках на
нескольких складах сначала нужно явно выбрать склад текущей бочки в карточке.

Миграция применена в Timeweb 29.09.2026 после отдельного подтверждения
владельца и проверки свежей резервной копии №105466011. Подробности:
[журнал применения](bulk-oil-barrels-timeweb-migration-2026-09-29.md).
Для проверки совместимости выпуска целевая миграция —
`APP_EXPECTED_MIGRATION=20260929120000_bulk_oil_barrels`. Запуск приложения
не выполняет миграции. Если до включения отдельного учёта уже были задания AQSI
со старым кодом, сначала проверить их состояние и фактический остаток текущей
бочки: исторические списания нельзя восстанавливать автоматически.

- `npx tsc --noEmit --incremental false`.
- ESLint новых серверных функций, API и компонентов.
- `npm run test:bulk-oil-barrels` — 18 сценариев на отдельной локальной PostgreSQL;
  скрипт допускает только localhost и базу `eco_barrels_test`.
- Сценарии включают приёмку, перенос текущей бочки, дубли кодов, расхождения,
  реальные складские списания, повторные и параллельные продажи, очередь AQSI,
  откат транзакций, филиальную изоляцию, отмену и повторное проведение приёмки.
- Подготовленный SQL применён на второй локальной базе с прежней схемой.
- Компоненты проверены в Chromium с реальными стилями проекта: обязательная
  причина, выбор бочки, сумма литров, отсутствие переполнения при ширине 390 px.
  Полная production-сборка Next.js поверх актуального `main` успешно завершена
  перед публикацией. Проверка физической кассы не выполнялась.
