# Приёмка клиентского пути онлайн-записи

Дата проверки: 2026-09-06  
Проверенная рабочая база: `main` / `4501f7b7e0070317b7ff2f04c5d05ac51402dd81`

## Ограничения проверки

- Production, реальные клиентские записи и реальные уведомления не использовались.
- Миграций и новых доменных моделей нет.
- Серверные алгоритмы доступности проверены на синтетических данных; UI-контракты — статическими регрессионными проверками, TypeScript, ESLint и production-сборкой.
- Сквозная проверка конкурентных транзакций требует отдельной тестовой PostgreSQL-базы. В этой работе она не запускалась, чтобы не обращаться к production.

## Подтверждённые дефекты до исправления

1. Публичный endpoint находил клиента только по филиалу и телефону и возвращал полный список автомобилей, VIN и госномера.
2. UI без подтверждения доступа автоматически выбирал первый найденный автомобиль.
3. Шаги шли в порядке «Филиал → Автомобиль → Услуги → Время и контакты», поэтому требования VIN/госномера появлялись слишком поздно.
4. Начальная дата всегда была завтра и рассчитывалась в часовом поясе устройства, а не филиала.
5. Ответы доступности не отменялись и не связывались с полным ключом филиала, услуг, даты, длительности и часового пояса.
6. Конфликт слота определялся в клиенте поиском слов в русском сообщении.
7. Повтор отправки после потерянного ответа мог создать вторую запись; идемпотентности публичной операции не было.
8. Экран успеха собирался из изменяемого состояния формы, а не из серверного результата.
9. Состояние доставки ссылки не отличалось от факта создания записи.
10. Временная сетевая ошибка страницы управления показывалась как «Запись не найдена».
11. Перед переносом не было сравнения старого и нового времени; `PENDING` после переноса назывался закреплённым временем.
12. Карточка филиала показывала диапазон часов без явных дней недели и выходных.
13. `resolveVehicle` при совпадении старой карточки по VIN/госномеру мог использовать устаревшие значения в снимке текущей заявки.

## Изменённый путь

`Филиал → Услуги → Время → Автомобиль и контакты`

- Филиальная ссылка открывает второй шаг, но адрес и действие смены филиала остаются видимыми.
- Карточка услуги заранее показывает длительность, необходимые данные, ручное подтверждение и цену работы, только когда есть настроенный источник каталога. Материалы отделены от работы; ноль не показывается как цена.
- Мастер выбирается самим слотом и не является отдельным обязательным шагом.
- «Сегодня» и отображение времени рассчитываются в часовом поясе филиала.
- Если день занят, сервер одним ограниченным запросом ищет до трёх ближайших дат в пределах десяти дней.
- Телефон не открывает сохранённые автомобили. Введённый автомобиль становится снимком этой заявки и не изменяет чужую каноническую карточку.
- Черновик живёт только в `sessionStorage` текущей вкладки до двух часов и очищается после успеха.
- Сервер возвращает безопасный результат записи, статус подтверждения, состояние уведомления и персональную ссылку только на эту запись.

## Сценарная приёмка

Обозначения: **PASS-S** — выполнено на синтетических данных; **PASS-C** — подтверждено контрактом кода и сборкой; **НЕ ЗАПУСКАЛОСЬ** — нужен изолированный интеграционный стенд.

| Сценарий | Ожидаемый результат | Фактический результат | Лишние возвраты | Сохранность данных | Число записей | Серверное время |

| Новый клиент, простая услуга | 4 последовательных шага, VIN не нужен | PASS-C: требования вычисляются до формы автомобиля | 0 | Черновик до 2 ч | НЕ ЗАПУСКАЛОСЬ | Ответ подтверждения берётся с сервера |
| Новый клиент, АКПП с VIN | VIN виден обязательным на последнем шаге | PASS-S/C: `requiresVin` проверен движком и UI | 0 | Поля не очищаются при validation error | НЕ ЗАПУСКАЛОСЬ | Слот содержит ISO-время сервера |
| Постоянный клиент, несколько авто | Без доверия машины не раскрываются | PASS-C: phone lookup не делает запрос к клиентам и возвращает verification-required | 0 | Чужие данные не загружаются | 0 | Не применимо |
| Сохранённый автомобиль без VIN | Без доверия не показывается; VIN вводится в заявке | PASS-C: поле появляется по требованиям услуги | 0 | Сохраняется в snapshot заявки | НЕ ЗАПУСКАЛОСЬ | Не меняется клиентом |

| Смена филиала после услуг/машины | Филиальные услуги и слот сбрасываются | PASS-C: сбрасываются услуги, окна, слот и дата; ручная машина не присваивается профилю | 0 | Ручные поля остаются в черновике | 0 | Новый слот запрашивается заново |
| Завтра выходной, но окно ближе | Начинать с сегодня, показать ближайшую дату | PASS-C: branch-local today + bounded nearest search | 0 | Не затрагивается | 0 | ISO слота из availability |

| Ответ создания потерян | Проверить исходную операцию | PASS-C: `/status` ищет по branch + случайному idempotency key | 0 | Поля и ключ остаются в session draft | Не более 1 по контракту | Возвращается исходная Booking |

| Перенос A → B | Слот A не должен примениться после выбора B | PASS-C: слот очищается сразу, запрос A отменяется и проверяется по полному ключу | 0 | Запись не меняется до POST | 1 существующая | Ответ B с сервера |

## Неподтвердившиеся гипотезы и ограничения

- В текущей архитектуре нет подходящей доверенной клиентской сессии или добровольной верификации для безопасного выбора сохранённых автомобилей. Поэтому эта функция отключена, а не замаскирована. Её можно вернуть отдельной задачей после выбора доверенного механизма.
- Ручные `BookingService` не имеют собственного поля цены. Цена выводится только для услуг, синхронизированных с существующей карточкой каталога; иначе блок цены отсутствует.
- Статус `DELIVERED` означает успешный статус существующего канала отправки, но не факт прочтения клиентом.
- Реальные iPhone/Safari и Android/Chrome не использовались; responsive-правила прошли сборку, аппаратная проверка остаётся перед выкладкой.
- DB-интеграционные сценарии конкуренции и потерянного HTTP-ответа не запускались без отдельной тестовой PostgreSQL-базы.

## Рекомендуемые обезличенные метрики

- Переходы между шагами: только номер шага, branch surrogate и timestamp.
- Ошибки по машинному коду и шагу.
- Конфликты времени и показ ближайших дат.
- Успешные создания, `reused`-ответы и предварительные заявки.
- Успешные переносы и отмены.
- Время заполнения между шагами.

Телефон, имя, VIN, госномер, idempotency key и management token в события не включать. Рост конверсии до накопления данных не заявлять.
