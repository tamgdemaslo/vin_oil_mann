# Дорожная карта: записи клиентов

Дата выгрузки: 2026-05-26  
Основной маршрут экрана: `/records`  
Редирект: `/clients` -> `/records`  
Цель документа: передать в Figma полную карту текущего сценария записей клиентов, все поля, состояния, payload и интеграции.

## Источники в коде

- `src/app/records/page.tsx` — основной экран журнала записей, календарь, создание, редактирование, удаление.

- `src/app/clients/page.tsx` — редирект `/clients` на `/records`.
- `docs/design-brief.md` — общий сценарий CRM и записей.

## Роли и входные условия

| Условие | Поведение |
|---|---|
| Пользователь не авторизован | Редирект на `/login?from=/records`. |
| Роль не `owner` и не `admin` | Показывается ошибка доступа: `Доступ к разделу записей есть только у владельца и администратора.` |
| Нет `YCLIENTS_COMPANY_ID` | Показывается ошибка: `Не задан YCLIENTS_COMPANY_ID в .env.local`. |
| Для records/record/company/timetable нет user token | Backend вернет 401 с подсказкой добавить `YCLIENTS_USER_TOKEN` или `YCLIENTS_USER_LOGIN`/`YCLIENTS_USER_PASSWORD`. |
| Доступ есть | Загружается конфигурация филиала, сотрудники, услуги, график и записи на выбранную дату. |

## Карта сценария

1. Пользователь открывает `CRM -> Журнал записей` (`/records`).
2. Система проверяет авторизацию и роль.
3. Система загружает конфиг YClients: `company_id`, `company_title`.
4. Система загружает сотрудников и услуги филиала.
5. Система выбирает сотрудника для таймлайна: первый `bookable`, иначе первый из списка.
6. Система загружает график и записи на выбранную дату.
7. Пользователь смотрит журнал в виде таймлайна 08:00-17:00.
8. Пользователь меняет дату, сотрудника или нажимает `Обновить`.
9. Пользователь создает запись через кнопку `Новая запись`, карточку ближайшего свободного окна или клик по пустому слоту таймлайна.
10. Пользователь заполняет сотрудника, услугу, клиента, время и комментарий.
11. Backend отправляет `create-record` в YClients. Клиент создается автоматически вместе с записью.
12. Пользователь выбирает существующую запись на таймлайне.
13. В правой панели открывается карточка записи: клиент, телефон, комментарий, связанные отгрузки, действия.
14. Пользователь может открыть комментарий, создать отгрузку, редактировать или удалить запись.
15. При редактировании backend отправляет `update-record`; при удалении — `delete-record`.

## Payload создания записи

UI отправляет на `/api/yclients`:

```json
{
  "action": "create-record",
  "company_id": "companyId",
  "payload": {
    "phone": "79990000000",
    "fullname": "Имя клиента",
    "email": "client@example.com",
    "comment": "Комментарий или undefined",
    "appointments": [
      {
        "id": 1,
        "services": [123],
        "staff_id": 456,
        "datetime": "2026-05-26 10:30:00",
        "seance_length": 2400
      }
    ]
  }
}
```

Backend проксирует это в YClients:

| Поле | Правило |
|---|---|
| `action` | Должен быть `create-record`. |
| `company_id` | Из конфига или env fallback. |
| `phone` | Нормализованная строка цифр. |
| `fullname` | Trim из имени клиента. |
| `email` | Если пользователь не указал email, создается временный `phone@temp.mail`. |
| `comment` | Отправляется только если не пустой. |
| `appointments[0].id` | Всегда `1`. |
| `appointments[0].services` | Массив из одного id услуги. |
| `appointments[0].staff_id` | Id сотрудника. |
| `appointments[0].datetime` | Начало записи, секунды всегда `:00`. |
| `appointments[0].seance_length` | Секунды: разница между началом и окончанием или длительность услуги. |

Важно: отдельное создание клиента (`create-client`) в API отключено. Клиент создается автоматически при создании записи.

## Payload редактирования записи

UI отправляет на `/api/yclients` методом `PUT`:

```json
{
  "action": "update-record",
  "company_id": "companyId",
  "record_id": 123456,
  "payload": {
    "staff_id": 456,
    "services": [{ "id": 123 }],
    "client": {
      "name": "Имя клиента",
      "phone": "79990000000",
      "email": "client@example.com"
    },
    "datetime": "2026-05-26 10:30:00",
    "seance_length": 2400,
    "comment": "Комментарий или undefined",
    "save_if_busy": true
  }
}
```

Backend проксирует это в YClients: `PUT /record/{companyId}/{recordId}`.

## API YClients: действия

| Action | Method UI -> backend | Backend endpoint YClients | Назначение |
|---|---|---|---|
| `config` | GET | Env only | Возвращает `company_id`, `company_title`. |
| `companies` | GET | `/companies` | Список доступных компаний и default company id. |
| `services` | GET | `/book_services/{companyId}` | Услуги для записи. |
| `staff` | GET | `/book_staff/{companyId}` | Сотрудники. Может принимать `service_ids[]`. |
| `dates` | GET | `/book_dates/{companyId}` | Доступные даты. На экране `/records` сейчас не используется напрямую. |
| `times` | GET | `/book_times/{companyId}/{staffId}/{date}` | Доступное время. |
| `seances` | GET | `/timetable/seances/{companyId}/{staffId}/{date}` | Сеансы/график. |
| `clients` | GET | Возвращает ошибку | Список клиентов через booking API недоступен. |
| `records` | GET | `/records/{companyId}` | Записи на период и сотрудника. |
| `create-record` | POST | `/book_record/{companyId}` | Создание записи и клиента. |
| `auth` | POST | `/auth` | Получение runtime user token по логину/паролю. |
| `update-record` | PUT | `/record/{companyId}/{recordId}` | Редактирование записи. |
| `delete-record` | DELETE | `/record/{companyId}/{recordId}` | Удаление записи. |

## Связка с отгрузками

Когда выбрана запись с телефоном клиента:

1. Телефон нормализуется.
2. Экран вызывает `/api/demands/by-phone?phone={phone}&limit=5`.
3. Backend ищет отгрузки в локальной синхронизации и live в МойСклад.
4. В правой карточке показываются последние найденные отгрузки.
5. Кнопка `Создать отгрузку` открывает `/shipment/new` с query:

```text
/shipment/new?counterparty={selectedClientName}&phone={selectedShipmentPhone}
```

## Связанная публичная запись с клиентского сайта

Это отдельный клиентский flow в `src/app/client-site/ClientSiteApp.tsx`: подбор по VIN -> выбор масла/фильтров -> выбор слота -> подтверждение записи. Он не пишет напрямую в YClients, а сохраняет демо/локальную заявку через `/api/appointments`.

### Поля публичной заявки

| Поле | UI / payload | Обязательность | Примечание |
|---|---|---|---|
| Имя | `name` | Да | Минимум 2 символа. |
| Телефон | `phone` | Да | Минимум 10 цифр. |
| VIN | `vin` | Да | Ровно 17 символов. |
| Масло | `oilId` | Да | Выбранное масло после VIN-подбора. |
| Слот | `slotId` | Да | Должен существовать и быть свободным. |
| Комментарий | `comment` | Нет | Автогенерируется: масло, фильтры, итог. |

### Поля публичного слота

| Поле | Примечание |
|---|---|
| `id` | Формат `{dateIso}-{HHmm}`. |
| `day` | `СЕГ`, `ЗАВ` или день недели. |
| `date` | Человеческая дата. |
| `weekday` | День недели. |
| `time` | Время. |
| `available` | Занят ли слот уже созданной заявкой. |

## Замечания для редизайна

- Списочный вид в сегменте есть визуально, но disabled. Для Figma лучше либо спроектировать будущий список, либо убрать переключатель из текущего макета.
- В создании записи можно выбрать только одну услугу, а в редактировании — несколько. Это расхождение стоит согласовать.
- Нет отдельного loading state у кнопок `Создать запись` и `Сохранить изменения`.
- `Закрыть` modal создания не сбрасывает введенные поля.
- Таймлайн жестко ограничен 08:00-17:00, хотя YClients может вернуть другие часы.
- Клик по занятой карточке останавливает propagation, клик по пустому месту создает запись. Это важно сохранить в интерактивном прототипе.
- Отдельный поиск клиента в YClients недоступен: клиент вводится вручную и создается автоматически при создании записи.
- Публичная запись с клиентского сайта сейчас хранится в памяти процесса через `/api/appointments`, это не тот же источник данных, что журнал `/records`.
