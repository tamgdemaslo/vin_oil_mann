# Карта отчета диагностики для Figma

Дата подготовки: 2026-06-01  
Экран: публичный отчет клиента по диагностике  
Маршрут: `/report/[token]`  
Назначение: передать дизайнеру структуру экрана, все поля, состояния и состав карточек для макета в Figma.

## Коротко о сценарии

Клиент получает публичную ссылку на отчет диагностики автомобиля. Авторизация не нужна. В отчете показываются:

- шапка автомобиля и общий статус;
- счетчики `В норме`, `Требует внимания`, `Рекомендуем заменить`;
- красная зона: что лучше сделать сейчас;
- желтая зона: что можно запланировать на следующий визит;
- фото, теги, замеры и рекомендации мастера;
- свернутый список нормальных пунктов;
- включение напоминания о ТО через 6 месяцев;
- быстрые действия: записаться, позвонить, согласовать.

Зеленые пункты не должны перегружать отчет: они показываются только счетчиком и раскрываемым списком.

## Структура экрана

| Блок | Компонент | Содержимое | Поведение |
|---|---|---|---|
| Page shell | `ReportPage` | Фон, общий контейнер, вертикальная сетка | Desktop: ширина контента до `1080px`; mobile: 1 колонка. |
| Hero | `ReportHero` | Бренд, тип отчета, авто, мета, мастер, общий статус, телефон | Первый экран должен сразу объяснять, чей это отчет и насколько все срочно. |
| KPI summary | `ReportSummary` | 3 счетчика: норма, внимание, замена | Всегда виден после hero. |
| Conclusion | `SummaryConclusion` | Текстовый вывод по результатам | Генерируется из количества красных и желтых пунктов. |
| Red section | `UrgentSection` | Список карточек `RED` | Если пусто, показать пустое состояние `Срочных работ нет`. |
| Yellow section | `NextVisitSection` | Список карточек `YELLOW` | Если пусто, показать пустое состояние `Плановых рекомендаций нет`. |
| Normal section | `NormalAccordion` | Свернутый список `GREEN` | По умолчанию закрыт, чтобы отчет был коротким. |
| Reminder | `ReminderPanel` | Чекбокс напоминания через 6 месяцев | Сохраняет `clientWantsReminder`. |
| Mobile CTA | `MobileStickyActions` | `Записаться`, `Позвонить` | Только mobile, закреплен снизу. |
| Lightbox | `PhotoLightbox` | Большой просмотр фото, навигация, закрытие | Открывается по нажатию на фото. |

## KPI summary

| KPI | Source | Цветовой смысл | Пример |
|---|---|---|---|
| В норме | `header.summaryGreen` | Зеленый, исправно | `12 пунктов` |
| Требует внимания | `header.summaryYellow` | Желтый, контроль | `2 пункта` |
| Рекомендуем заменить | `header.summaryRed` | Красный, действие сейчас | `1 пункт` |

Текст вывода под KPI:

| Условие | Текст |
|---|---|
| Есть красные и желтые | `По результатам проверки есть N пунктов, которые лучше устранить в ближайшее время, и M пунктов для контроля на следующем визите.` |
| Есть только красные | `По результатам проверки есть N пунктов, которые лучше устранить в ближайшее время.` |
| Есть только желтые | `По результатам проверки есть N пунктов для контроля на следующем визите.` |
| Нет проблем | `По результатам проверки критичных рекомендаций нет. Плановое обслуживание можно проходить по регламенту.` |

## Карточка рекомендации

Карточка используется и в красной, и в желтой зоне.

| Поле / зона | Source | Условие | UI-пример |
|---|---|---|---|
| Статус | `position.status` | Всегда | `Замена` для `RED`, `Внимание` для `YELLOW` |
| Название узла | `position.node` + каталог | Всегда | `Тормозная жидкость` |
| Что обнаружено | `position.tags` или fallback по статусу | Всегда | `Обнаружено: Давно не менялась.` |
| Рекомендация | `position.recommendation` | Если пусто, fallback | `Рекомендация: Замена тормозной жидкости.` |
| Замер | `measurementValue + measurementUnit` | Если есть значение или единица | `Замер: 3.20 %` |
| Теги | `position.tags` | Если есть | До 6 тегов, затем `Ещё N` |
| Фото | `position.photos[]` | Если есть | Сетка миниатюр 2 колонки, клик открывает lightbox |
| Нет фото | derived | Если фото нет | `Фото не добавлено.` |
| Красная подсказка | `status === RED` | Только красная карточка | `Лучше запланировать работу в ближайшее время.` |
| Что сделать | derived | Всегда | `Запланировать: Замена тормозной жидкости.` |
| CTA | derived | Всегда | `Записаться на замену` для `RED`, `Добавить напоминание` для `YELLOW` |

### Варианты карточки

| Variant | Отличия |
|---|---|
| `RecommendationCard / Red / With Photos` | Красная левая полоса, красный badge, фото, CTA `Записаться на замену`. |
| `RecommendationCard / Red / No Photos` | Вместо галереи текст `Фото не добавлено.` |
| `RecommendationCard / Yellow / With Measurement` | Желтый badge, блок замера, CTA напоминания. |
| `RecommendationCard / Yellow / Many Tags` | Показывать 6 тегов и chip `Ещё N`. |
| `RecommendationCard / Empty Recommendation` | Fallback `Согласовать дальнейшие действия с мастером.` |

## Фото и lightbox

| Поле | Source | Примечание |
|---|---|---|
| `photo.id` | `photos[].id` | Используется как key и для URL. |
| `photo.url` | `/api/diagnostic/public/[token]/photo/[photoId]` | Публичный доступ только по валидному token. |
| `photo.caption` | `photos[].caption` | Если пусто, alt = название узла. |
| Номер фото | derived | В lightbox: `1 из 3`, если фото больше одного. |
| Название | node title | В lightbox: название проверяемого узла. |
| Навигация | derived | Стрелки `previous / next`, клавиши в коде: Escape, ArrowLeft, ArrowRight. |

## Напоминание

| Поле | Source | Тип | Поведение |
|---|---|---|---|
| Напоминание включено | `clientWantsReminder` | boolean | Управляет checkbox и текстом кнопки. |
| CTA в желтой секции | same | button | `Напоминание добавлено` или `Напомнить через 6 месяцев`. |
| Панель внизу | same | checkbox | `Напоминание включено` / `Напоминание выключено`. |
| API сохранения | `POST /api/diagnostic/public/[token]/reminder` | action | Body: `{ clientWantsReminder: boolean }`. |

Важно для дизайна: напоминание сейчас только сохраняет желание клиента. Автоматическая рассылка через 6 месяцев в этом разделе не реализована.

## Нормальные пункты

| Поле | Source | Поведение |
|---|---|---|
| Счетчик | `header.summaryGreen` | Показывается в summary и заголовке accordion. |
| Список | `normalPositions[]` | По умолчанию скрыт в `details`. |
| Название пункта | `normalPositions[].node` + каталог | Например `Моторное масло`. |
| Empty fallback | derived | Если список не пришел: `Нормальные пункты скрыты, чтобы отчёт не превращался в полный внутренний чек-лист.` |

## Payload публичного отчета

```ts
type PublicDiagnosticReport = {
  header: {
    brand: string | null;
    model: string | null;
    year: number | null;
    licensePlate: string | null;
    mileage: number | null;
    vin: string | null;
    startedAt: string;
    completedAt: string | null;
    summaryGreen: number;
    summaryYellow: number;
    summaryRed: number;
    mechanicLogin: string | null;
  };
  clientWantsReminder: boolean;
  positions: ReportPosition[];
  normalPositions: NormalPosition[];
};

type ReportPosition = {
  id: string;
  block: DiagnosticBlock;
  node: string;
  status: "YELLOW" | "RED";
  tags: string[];
  measurementValue?: string | number | null;
  measurementUnit?: string | null;
  recommendation: string | null;
  photos: ReportPhoto[];
};

type ReportPhoto = {
  id: string;
  caption: string | null;
  url: string;
};

type NormalPosition = {
  id: string;
  block: DiagnosticBlock;
  node: string;
};
```

## Что важно не потерять в дизайне

- Отчет должен быть понятен клиенту без терминов из внутренней диагностики.
- Красная зона должна визуально вести к действию `Записаться / Позвонить`.
- Желтая зона должна быть спокойнее и вести к напоминанию.
- Фото должны быть заметными, потому что они повышают доверие к рекомендации.
- Зеленые пункты не должны занимать основной экран.
- На mobile основные действия должны быть доступны внизу без прокрутки к началу.
- Длинные названия узлов и рекомендации должны переноситься без обрезки.
- В отчете нельзя показывать служебные id, внутренние статусы, id отгрузки и полный логин мастера.
