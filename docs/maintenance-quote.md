# Единый расчёт ТО в отгрузке

Автомобиль определяется в одной карточке: VIN, госномер или ручной выбор MANN. Подбор масла и фильтров изменяет `positions` самой отгрузки. Отдельного набора строк и отдельного итога нет.

Выбор другого масла заменяет выбранный комплект масла (в том числе несколько фасовок), сохраняя прочие позиции. Выбор другого фильтра заменяет ранее выбранную позицию той же категории. Поиск товаров, комплекты и услуги доступны через раскрываемое ручное добавление.

Позиции Роско сохраняются как структурированные разовые товары с розничной ценой, источником и сроком. Остатки поставщика не являются складскими остатками филиала. Закупочная цена остаётся неизвестной до покупки: черновик сохраняется, проведение блокируется штатной проверкой себестоимости. Заказ поставщику не создаётся автоматически.

В существующем JSON позиции сохраняется `maintenance`: категория, ключ выбора, артикул MANN, идентификатор предложения, срок, время проверки, параметры масла и контекст автомобиля. Поле проходит чтение/нормализацию через `readShipmentMaintenance`. Схема БД не меняется.

Предложение клиенту строится из тех же позиций и скидок; закупочная цена и технические идентификаторы в него не попадают. Сохранение, автосохранение и повторное открытие используют стандартные API отгрузки.

По умолчанию первыми показаны товары со своего склада, затем предложения Роско по сроку и цене. Предложения одного товара объединены; другие склады раскрываются внутри. Сначала видны три товара.

Проверки: `npm run test:maintenance-quote`, `npm run test:shipment-maintenance`; интеграционный `scripts/test-shipment-maintenance-db.mjs` допускает только изолированную локальную БД `eco_maintenance_test` на порту 55447. Публикация выполняется через main / Timeweb App Platform.
