# Единый расчёт ТО в отгрузке

Расчёт ТО раскрыт сразу в основной области создания и редактирования отгрузки, перед поиском позиций. В просмотре сохранённой отгрузки тот же компонент расположен перед вкладками состава, VIN и диагностики. Старые карточки «Готовый расчет ТО для клиента» удалены. Для начала расчёта автомобиль не обязателен: допуск, вязкость, объём и артикулы MANN можно указать вручную. Подбор автомобиля передаёт профиль и найденные фильтры в уже доступный расчёт; отдельного расчёта внутри подбора больше нет.

- Допуск, вязкость и объём выбираются через компактные поля с поиском по вводу: полный список открывается по фокусу или кнопке со стрелкой и прокручивается без ввода, доступны выбор мышью и стрелками/Enter, закрытие Escape и ввод собственного значения. Для допусков есть разделы «Автомобиль», OEM, ACEA, API и ILSAC. Ввод обновляет расчёт после паузы 350 мс; выбор из списка и уход из поля применяют значение сразу. Нормализованные требования автомобиля вычисляются повторно только при изменении профиля. Для нестандартных значений есть ручной ввод.
- Единственный нормализованный допуск, вязкость и точный объём проверенного профиля подставляются по мере загрузки, включая данные, полученные после открытия расчёта. Диапазоны и предварительные объёмы пользователь уточняет вручную.
- Масла подбираются по нормализованным характеристикам моторных масел, с приоритетом OEM над ACEA/API/ILSAC. Неизвестный допуск не превращается в подбор только по вязкости.
- Наличие берётся из выбранного склада текущего филиала; товары другого филиала недоступны. API требует авторизацию и доступ к филиалу. В ответе нет закупочных цен.
- Продажа в литрах считается по нужному объёму, продажа канистрами округляется до целого числа упаковок. Без объёма фасовки или положительной цены товар выбрать нельзя.
- Одинаковая линейка масла в разных фасовках объединяется в один вариант. Для нужного объёма подбирается комплект доступных упаковок с минимальным излишком, затем с минимальной стоимостью. Например, 4 л и 1 л образуют один комплект на 5 л. Разные линейки и продажа на розлив остаются отдельными вариантами. Расходники и работа общие для всех вариантов. Найденные масляный, воздушный и салонный фильтры MANN доступны прямо в расчёте: при выборе совместимого складского товара фильтр сразу добавляется в расчёт; цена редактируется прямо рядом с выбором. При открытии расчёта для каждого артикула MANN автоматически запрашиваются предложения Роско: исходный MANN и его прямые аналоги из `crosses.Part`. Посторонние результаты поиска и аналоги второго уровня не включаются; одинаковые складские предложения объединяются. Допускаются только положительные цена и остаток, без комплектов с кратностью больше единицы. Показаны розничная цена с наценкой филиала, остаток у поставщика и интервал даты и времени доставки в часовом поясе филиала (или срок в днях, если даты отсутствуют); неизвестный срок обозначается явно. Закупочная цена в браузер не передаётся. Предложения можно сравнить в раскрываемом списке и отсортировать «Дешевле» или «Быстрее» без повторного запроса. По умолчанию предложения идут по ближайшей доставке, затем по цене; тот же порядок используется в списке выбора товара. Если исходный MANN недоступен, сравнение аналогов открывается автоматически. Неизвестный срок стоит после известных при сортировке по доставке. Аналоги явно подписаны как связи Роско; применяемость нужно сверить с автомобилем. При выборе сохраняются реальный бренд и артикул аналога, цена, срок и исходный артикул MANN; они попадают в расчёт и сообщение клиенту. Кнопка «Обновить Роско» повторяет запрос. При ошибке интеграции складские и ручные варианты остаются доступны. Можно также добавить найденный артикул MANN и указать цену. Поиск товара/услуги по названию или артикулу и ручные строки тоже доступны.
- Изменение требований очищает выбор масла. Изменение автомобиля или модификации сбрасывает расчёт. Склад можно выбрать прямо из расчёта: открываются параметры документа. При выборе или смене склада параметры масла, ручные строки и артикулы MANN без привязки к наличию сохраняются; складские предложения очищаются. Расчёт сохраняется в состоянии страницы отгрузки, без записи в базу; сворачивание расчёта или закрытие автоподбора не удаляет выбранные строки. При уходе со страницы предложение нужно скопировать. Можно подготовить предложение только с фильтрами/работой без выбора масла.
- Кнопка копирует сообщение с составом каждого варианта и итогом; ручное копирование из предварительного просмотра доступно при ограничениях буфера обмена.

Расчёт предварительный: остатки не резервируются, документы и оплаты не создаются. Применяемость выбранного фильтра подтверждается существующим подбором фильтров; поиск по складу сам по себе не подтверждает совместимость.

Проверки: `npm run test:maintenance-quote`, TypeScript, ESLint изменённых новых модулей. Браузерный сценарий проверен на реальном компоненте с изолированным демонстрационным API, включая два варианта, фильтр, работу, копирование и ширину 390 px. Проверка с рабочей базой и публикация отдельно.

В сохранённой отгрузке данные прежнего VIN-подбора передаются как подсказки; диапазон объёма не выбирается автоматически. В Роско отправляются только явно распознанные артикулы MANN, не OEM-номера других брендов. Складские варианты ограничиваются складом документа. Артикул MANN, введённый вручную, помечается как требующий проверки применяемости.


### Mercedes W203: legacy VIN ambiguity

TRONK `vindecode` can return the whole W203 engine range and `vindecode2`
can return no data. The verified manufacturer type crosswalk currently covers
`WDB…` type `203045`: C 200 Kompressor (203.045), M111.955. It selects only a
single matching provider report with compatible displacement and power;
unsupported types or conflicting reports remain unselected. It does not infer
a build year from catalogue production dates.

The M111.955/W203 oil reference is independent of local MANN filter coverage:
MB 229.5, 7 l with filter. Evidence: Daimler WIS BF18.00-P-1001-01L and
[Ravenol's 203.045 application](https://choise.ravenol.com/1-cars/365-mercedes-benz/1433-c-klass-w203-s203-cl203/83364-c-200-kompressor-203-045245745/).
Identity crosswalk: [Hengst](https://catalog.hengst.com/en/online-catalog/product/7835310000-01/de/).
Viscosity is not inferred as a unique value from an approval that permits
multiple grades. Filter catalogue gaps do not substitute a later M271 engine.


### PartsAPI → MANN → технические данные

`normalizePartsApiMannCard` сохраняет название модификации, код исполнения,
коды двигателя, кузов, объём, мощность и границы применяемости каталога.
Границы `yearOfConstrFrom/To` не становятся годом выпуска конкретной машины.
`manufacturerTypeCodes` извлекает код из названия модификации, а не из номера
двигателя или VIN-серийного номера.

Сопоставление использует общую нормализацию марки/модели, кузов, двигатель,
мощность, объём и код исполнения. Автоматический выбор допускается только при
высокой уверенности, достаточном отрыве от второго кандидата, отсутствии
противоречий и точном признаке двигателя/исполнения либо совпадении
модификации вместе с объёмом и мощностью. Равнозначные кандидаты остаются для
выбора; неизвестные поля не заполняются предположениями.

Историческая проверка отклоняла карточку PartsAPI с несовпадающим VIN и использовала резервную расшифровку. По политике от 20.11.2026 такая карточка принимается при валидных марке/модели; VIN расчёта остаётся входным. Настроенный PartsAPI не переключается на TRONK при неоднозначности, пустом ответе или временной ошибке.

Для отсутствующей в PDF-импорте M111.955 добавлена отдельная запись официального
онлайн-каталога в `mann-reviewed-applications.ts`. Это дополнение каталога,
а не привязка к VIN-серийному номеру. Источники MANN/Hengst сохранены рядом с
записью. Совпадающая запись БД имеет приоритет. Эта же модификация используется
для чтения фильтров, технических профилей, сохранённых исследований и новых
запросов OpenAI. Начальный запуск приложения не импортирует строки в БД.

Сначала загружается технический профиль и проверенные справочные поля, затем
сохранённые связанные сведения из БД. Только после этого рассчитываются
пропуски по полям (допуск, сервисный объём, вязкость). Поиск выполняется двумя
запросами групп одновременно; каждая группа сохраняется транзакционно до
возврата ответа. Источник, цитата, организация и выбранная MANN-модификация
сохраняются вместе с данными. ИИ не заменяет уже заполненные поля. Найденные
данные имеют пометку проверки источника. При повторном подборе сведения
читаются из БД; для заполненных полей вызов OpenAI не нужен.

Таблица жидкостей и прогресс поиска отображаются вне свёрнутого блока уточнения
автомобиля. Тип/модель коробки и условное оборудование остаются неизвестными,
пока их не подтверждают входные данные или источники.

Локальная проверка: `npm run test:maintenance-vehicle-pipeline`.
Она воспроизводит записанный ответ PartsAPI с отличающимся VIN карточки, без обращения к TRONK, реальный
матчер и API технического профиля, четыре фильтра, чтение БД до поиска,
сохранение только недостающих полей и повторное чтение без OpenAI.
Транспорт OpenAI и Prisma-хранилище изолированы тестовыми адаптерами; тест не
обращается к production и не является проверкой внешнего провайдера вживую.

Структурированные поля `MannVehicleVariant` (объём, код двигателя, мощность,
топливо, поколение и кузова) дополняют разреженные строки PDF по тому же ключу
модификации до ранжирования. При отсутствии expand-таблицы сохраняется старый
путь по PDF-строкам. Списки альтернативных двигателей остаются списками;
автоматический выбор не применяется, если источник явно допускает несколько
двигателей. Поиск жидкостей использует тот же разбор сжатых кодов MANN.


### Подбор остальных жидкостей

Вкладка «Жидкости» использует подтверждённые применимые записи технического профиля. Метод обслуживания и точный сервисный объём выбираются в пределах одной записи агрегата; полная/сухая ёмкость и диапазоны не подставляются как сервисный объём. Если известна вязкость, её нельзя очистить и продолжить поиск. Для антифриза и тормозной жидкости без отдельного требования SAE отмечено, что SAE не применяется.

POST `/api/maintenance-quote/fluid-stock` принимает выбранный склад, немоторную систему, массив обязательных технических деклараций и необязательную SAE. Авторизация/активный филиал/принадлежность склада проверяются сервером. Подбор использует тип группы и положительные технические поля; название товара не доказывает совместимость, остатки других складов не суммируются. ГУР с точным требованием Dexron может использовать явно типизированный ATF того же класса; новые эквивалентности не вводятся.

Карточки не получают статус официального одобрения по наличию слова approval. Пока происхождение одобрения не подтверждено, оно остаётся `unknown` и мастер должен явно проверить применяемость. Перед добавлением повторно запрашиваются цена, фасовка, остаток и совместимость. Изменённые сведения требуют повторного подтверждения. Выбранная строка хранит агрегат, метод, сервисный объём и объём к покупке; устаревшие строки блокируют клиентский текст. Жидкости включены в общие итоги и каждый альтернативный вариант моторного масла. Предложения РОССКО для немоторных жидкостей доступны через явно выбранную цифровую карточку; фильтры используют отдельный существующий путь.

Клиентские строки фильтров содержат тип, бренд и цену, включая случаи с метаданными поставщика. Артикулы, поставщик и доставка остаются в интерфейсе мастера.


### Немоторные жидкости у поставщика и применимость сохранённых фактов

Подбор у РОССКО выполняется через `/api/maintenance-quote/fluid-rossko`: подходящая цифровая карточка → явный запрос точного артикула → актуальное предложение → подтверждение совместимости, упаковки и поставки. Кратность учитывается отдельно от сервисного объёма. При отсутствии единицы и фасовки в ответе используются явные поля точной актуальной карточки с предупреждением и ручной проверкой; противоречия блокируют добавление. Перед добавлением предложение запрашивается повторно, изменение условий сбрасывает подтверждение. Реальные вызовы поставщика в локальной проверке не выполняются.

Сохранённые исследования v4 привязаны к подтверждённым условиям автомобиля/агрегата. Каталожный диапазон лет MANN не заменяет фактический год. Факты без доказанной области не становятся автоматическими рекомендациями; причина видна и при пустом профиле. Смена коробки очищает прежний профиль до загрузки нового. Строка расчёта проверяет ревизию и модель агрегата, склад и тот же сервисный вариант. Старые факты сохранены; смена версии не разрешает повторный платный batch-поиск или дублирующий ручной импорт.


### Повторное использование подтверждений автомобиля

Технический запрос передаёт VIN и распознанные признаки КПП/привода. Сервер читает только паспорта активного филиала и подтверждения конкретных полей. Совпадения VIN недостаточно при конфликте идентичности; raw AUT и общий статус CONFIRMED не заменяют fieldSources. Сохранённый тип выбирает ту же ветку профиля и область исследований, явный новый выбор имеет приоритет. Сохранённая точная модель или число передач из класса АКПП не выводятся. Источник подтверждения подписан в интерфейсе. Подтверждение равного значения сохраняется отдельной ревизией без сброса MANN.

Несколько различных ответов декодера больше не превращаются в первый нормализованный кэш. Raw-ответ и список вариантов сохраняются, а очистка derived-identity проверяется до успешного завершения lookup. Исторические результаты требуют отдельного аудита неоднозначности; сам returnedVIN не доказывает единственную модификацию.

## Продолжение: проверка истории запросов и защита raw VIN

Read-only сверка исходных600 нашла459 VIN без сохранённой попытки в branch-main и9 удержанных прежних попыток среди468 неподтверждённых. Это очередь, а не новые расшифровки. Cache-only CLI резервирует метод+VIN до запроса, ведёт журнал без секретов, ограничивает бюджет, держит предыдущие попытки и не пишет технические факты. Предыдущие попытки других филиалов учитываются только EXISTS-проверкой.

Несовпавший VIN в raw-ответе TRONK сохраняется в карантине без normalized identity. Корневой VIN в протоколе TRONK — корреляция запроса, а не независимое доказательство конкретной машины: https://data.tronk.info/docs/vindecode и https://data.tronk.info/docs/vindecode2. Проверены кэшированный/новый mismatch, неоднозначность и изоляция пригодного fallback от карантина.

TRONK-пилот отклонён автоматической проверкой до запуска: требуется явное разрешение передать VIN именно TRONK и сохранить ответ в Timeweb. Вызовов этого пилота и его записей нет; разрешение запрошено, обход не выполнялся. В Timeweb подтверждено наличие настройки основного PartsAPI. Попытка одиночной команды через консоль не дала видимой квитанции; последующее read-only чтение не нашло строки PARTSAPI_RAW_PILOT_V1. Исход вызова не подтверждён, повтор не запускался. Снимок консоли отклонён из-за возможного VIN; вместо него сохранена обезличенная квитанция БД primary-pilot-db-receipt.json.

Ручная проверка официального позднего руководства Getz не дала применимых новых фактов для раннего1.3 G4EA:3.3л с фильтром относятся к другим двигателям. Новых технических фактов в этом продолжении нет. OpenAI API не вызывался. Production-код и схема не менялись.

Финальная isolated production-сборка завершилась успешно, включая TypeScript и282 страницы; SHA256 четырёх изменённых файлов совпали с рабочей копией. Журнал и manifest сохранены в приватных артефактах. Тесты ограничения запросов, cache scope, VIN identity и mocked pipeline прошли. Полная цель и90–95% покрытия не достигнуты.

## PartsAPI: политика по указанию пользователя от20.11.2026

VIN внутри карточки PartsAPI не используется как основание отклонить ответ на запрошенный VIN. При наличии валидных марки/модели нормализуются характеристики карточки; входной VIN остаётся VIN расчёта. Отсутствующий код двигателя не выдумывается: его может уточнить однозначное сопоставление модификации с MANN. Несколько модификаций сохраняются отдельными кандидатами. Для настроенного PartsAPI неоднозначность, пустой ответ и временная ошибка не запускают TRONK. Проверки TRONK не ослаблены.

Контрактный тест использует сохранённый реальный PartsAPI ответ WDB…398: карточка с другим VIN принята, C200Kompressor203.045 сопоставлен с MANN/M111.955 и четырьмя фильтрами; вызовов TRONK0. Отдельно проверены несколько вариантов, HTTP503 и пустой результат. Это локальная проверка на сохранённом ответе, не новый запрос провайдеру и не приёмка production. TypeScript прошёл; код не выкладывался.

### Чтение пакетного кэша PartsAPI

В контексте активного филиала сначала читается непросроченный `VinLookupCache` по `branchId` и VIN. Для `PARTSAPI_600_RAW_V1` используется вложенный `partsApiBatch`, если он существует. Сохранённые `decoded` и `not_found` возвращаются без запроса провайдеру, в том числе без настроенного API-ключа. Pending/error/неопределённый исход и ошибка чтения БД возвращают unavailable без повторной покупки. Межфилиальный контекст не читает кэш филиала. Отсутствующий или неподходящий кэш допускает обычный запрос PartsAPI. Флаг fromCache передаётся в диагностику интерфейса.
