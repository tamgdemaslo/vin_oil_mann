# Аудит полей товара

Дата аудита: 2026-06-27.

Объект хранения: `prisma/schema.prisma` → `LocalProduct` / таблица `local_products`.

Временный UI для live-статистики: `/inventory/products/audit`, доступ только `owner`/`admin`.

Проверенные зоны кода:

- Prisma schema и индексы `LocalProduct`;
- API карточки и списка товаров: `src/app/api/local-inventory/products/*`, `src/app/api/catalog/search/route.ts`;
- создание/редактирование товара: `src/app/inventory/products/ProductsClient.tsx`;
- поиск и фасеты: `src/lib/catalog-search.ts`, `src/lib/local-inventory-admin.ts`;
- импорт/экспорт: `src/lib/product-import-export.ts`;
- отгрузки и складские документы: `src/lib/local-demand-write.ts`, `src/lib/demand-detail-load.ts`, `src/lib/local-inventory-admin.ts`;
- инвентаризация и сканирование: `src/lib/warehouse-inventory.ts`;
- маркировка: `src/lib/product-marking.ts`, `src/lib/local-inventory-admin.ts`;
- ROSSKO: `src/lib/rossko.ts`, `src/app/api/rossko/search/route.ts`;
- публичные/клиентские подборы масел: `src/lib/public-oil.ts`, `src/lib/client-site-api.ts`;
- печатные и закрывающие документы просмотрены по зависимостям от позиций отгрузки.

Вывод: физически удалять поля сейчас нельзя. Безопасная стратегия на первом этапе: оставить модель и импорт/экспорт совместимыми, а рабочий UI карточки сделать компактным и динамическим.

## Решения по UI

- В основном блоке оставить одно рабочее поле `Код / штрихкод` на базе `code`.
- `barcodeEan13`, `barcodeEan8`, `barcodeCode128`, `externalCode`, `rossko*` перенести в `Дополнительные коды`.
- Цены продажи/закупки оставить только в `Главное`; складской блок показывает только остаток, доступно, резерв, ячейку, минимальный остаток и поставщика.
- Маркировку оставить отдельным блоком.
- Характеристики выбирать по `groupPath`, а не по названию товара:
  - масла: `sae`, `apiSpec`, `acea`, `aceaExtra`, `ilsac`, `atf`, `packageVolume`, `volume`, `oemAtf`;
  - фильтры: `mannName`, `oem`, `oemParts`, `mannCharacteristicName`;
  - прочее: профильных характеристик нет, старые значения скрываются, но не удаляются.
- `Дополнительно` переименовать в `Служебные данные` и держать свернутым.
- `Технические поля` оставить свернутыми и не дублировать поля, которые получили рабочие блоки.

## Миграция и совместимость

Миграция данных в этой итерации не выполнялась. Причина: старые EAN/Code128/OEM поля уже участвуют в поиске, импорте/экспорте и инвентаризации. Для будущей миграции нужен отдельный migration report:

- сколько товаров имеют `code` и несколько EAN одновременно;
- сколько товаров имеют конфликт `code` vs EAN;
- сколько товаров имеют `oem`, `oemParts`, `mannName` одновременно;
- какие товары требуют ручной проверки кодов.

До такой миграции все legacy-поля сохраняются в БД и продолжают участвовать в поиске.
