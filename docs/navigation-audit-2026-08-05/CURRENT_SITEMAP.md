# CURRENT_SITEMAP

Дата аудита: 5 августа 2026 года. Источник истины: `src/app/**/page.tsx`, текущий `PlatformShell`, меню пользователя, переключатель филиалов и проверки доступа в страницах/API. Это описание текущего состояния, а не утверждённая новая навигация.

## 1. Текущая карта входов

### Верхнее меню на desktop

```text
Главная
└─ Сводка / Все филиалы

Операции
├─ Все отгрузки
└─ Новая отгрузка

Склад
├─ Товары
├─ Аналитика товаров
├─ Инвентаризация
├─ Приёмка
├─ Корректировки
└─ Пополнение

Финансы
├─ Финансовый центр
├─ Касса
├─ Счета поставщиков
├─ Цены и прибыль
└─ Зарплата

CRM
├─ Дела клиентов
├─ Сообщения
├─ Записи
└─ Контрагенты

ИИ-помощник
├─ Рабочий чат
└─ Настройки

Кабинет
├─ Профиль
├─ Филиалы
├─ Аналитика клиентов
├─ ИИ-помощник
├─ Интеграции
└─ Мессенджеры
```

Особенности:

- все семь пунктов первого уровня работают как раскрывающие кнопки; даже «Главная» с одним дочерним пунктом не открывается прямым кликом;
- «Аналитика клиентов» и «ИИ-помощник» находятся одновременно в предметном разделе и в «Кабинете»;
- «Кабинет» одновременно означает личный профиль, филиалы, юрлица, интеграции, клиентские коммуникации и системные настройки;
- доступность пунктов определяется в основном устаревшей ролью `owner/admin/master`, а не фактическими ролями группы и филиала;
- режим «Все филиалы» отключает не только операции, но и большинство чтения/аналитики.

### Меню пользователя

```text
[Аватар, имя, роль, филиал]
├─ Кабинет
├─ Аналитика клиентов   (owner/admin)
└─ Выйти
```

В меню нет прямых входов в личные зарплату, уведомления, Telegram, безопасность и список доступных филиалов. Предметная «Аналитика клиентов» ошибочно размещена в персональном меню.

### Переключатель филиала

Показывает активные филиалы и, для групповой роли, «Все филиалы». Это только переключатель контекста: из него нельзя перейти в настройки текущего филиала или управление филиалами. Положительный паттерн — выбранный филиал повторяется в контекстной строке под шапкой.

### Mobile

Все дочерние ссылки семи desktop-разделов превращаются в один плоский длинный список. Название исходного раздела показано мелкой подписью, но группировки, приоритетов ежедневных задач, персонального меню и постоянной нижней навигации нет.

| Клиентские уведомления | 5: автосценарии, шаблоны, каналы, журнал отправок, переменные | это системная коммуникационная настройка, не «Кабинет» и не персональные уведомления |
| Инвентаризация | активные, проверка, проведённые, отменённые | понятная процессная группировка |
| Касса | открытие, активная смена, закрытые | понятная процессная группировка |

## 5. Найденные источники риска

### Интеграции: текущая обнаруживаемость

| Интеграция | Текущий пользовательский вход | Уровень / владелец | Проблема IA | Целевое место |
|---|---|---|---|---|
| T‑Bank | блок на `/cabinet/integrations` | FINANCE; секрет — владелец группы | находится рядом с несвязанными sync/debug; admin может дойти до owner-only save | Управление → Интеграции → Финансы → T‑Bank |
| МойСклад | два блока sync на `/cabinet/integrations` | BRANCH/INTEGRATIONS; склад и данные клиентов | выглядит как две разные интеграции, ручные задания смешаны с подключением | одна карточка МойСклад с разделами «Подключение/Синхронизации/Журнал» |
| YCLIENTS | `/records` как рабочий журнал | BRANCH/OPERATIONAL | рабочее использование видно, управление подключением не имеет явного канонического входа | Работа → Записи; настройка — Управление → Интеграции → Запись |
| Рабочий Telegram | `/cabinet/integrations/messenger` | BRANCH/COMMUNICATIONS | MTProto, account, webhook, media worker и sync собраны под общим «Мессенджеры» | Управление → Каналы связи → Рабочий Telegram |
| Личный Telegram | карточка в `/cabinet` | PERSONAL | не является внешней бизнес-интеграцией; текущий flow не завершается | меню пользователя → Мой Telegram |
| MANN | скрытый `/inventory/integrations/mann-pdf` | INTEGRATIONS/каталог | технический CSV import без входа/owner label | Управление → Интеграции → Каталоги → MANN |
| ROSSKO | действия/данные внутри товарного контура | INTEGRATIONS/поставщик | нет общей карточки статуса/владельца подключения | Управление → Интеграции → Поставщики → ROSSKO; рабочий поиск остаётся в Товарах |
| TRONK | данные VIN/госномера в автомобильном/диагностическом потоке | INTEGRATIONS/данные авто | интеграция проявляется только как источник внутри операции | Управление → Интеграции → Автомобили → TRONK; использование остаётся контекстным |
| OpenAI | `/ai-assistant`, `/cabinet/ai-assistant`, pricing | INTEGRATIONS/AI | рабочий инструмент и системная настройка дублируются в глобальном меню | ИИ-помощник для работы; Управление → ИИ и автоматизация для настройки |

Правило: рабочая функция провайдера остаётся в предметном процессе, а подключение, секреты, здоровье и журналы — в каталоге «Интеграции». Не следует заставлять мастера открывать «Интеграции», чтобы пользоваться Записями или поиском VIN.

- В кодовой базе одновременно существуют текущий `PlatformShell` и неиспользуемый `AppHeader` со старой структурой меню. Это два конкурирующих описания продукта.
- Фактическая ролевая модель поддерживает роли группы и филиала, но shell строит меню почти только по `owner/admin/master`.
- Не все страницы имеют одинаковый слой server-side gate: часть защищена страницей, часть только API, часть лишь disabled-ссылкой.
- Маршруты-алиасы полезны для deep links, но без единого реестра воспринимаются как дубли и увеличивают стоимость поддержки.
