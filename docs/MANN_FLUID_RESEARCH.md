# Поиск недостающих жидкостей при подборе

После обычного запроса технического профиля интерфейс отдельно вызывает тот же POST с `researchMissing: true`. Фильтры и каталог не ждут веб-поиск. Модель фиксирована: `gpt-5.6-terra`, существующий серверный `OPENAI_API_KEY`, общий фабричный OpenAI-клиент с настройками прокси.

## Поэтапный поиск

Клиент отправляет четыре независимых запроса с `researchGroup`: `basic` (масло, антифриз, тормозная жидкость), `transmission` (четыре типа КПП), `drivetrain` (редукторы и раздатка), `auxiliary` (ГУР и муфта). Одновременно работают максимум две группы. Один запрос исследует только свои 2–4 системы, лимит ответа — 4000 токенов, сетевой тайм-аут — 75 секунд. У каждой группы отдельная запись и кеш (`aggregate` включает `grouped_v1`, группу и пропуски). Успешный ответ отдаётся только после сохранения этой группы в БД.

Интерфейс обновляется после каждого ответа; готовые строки остаются видимыми, пока остальные ищутся. Сбой группы не очищает успешные группы. «Повторить незавершённые» отправляет только неуспешные группы (`retryFailed: true`); сервер не перезапускает успешный кеш, а повтор неуспешного задания проходит прежний лимит и блокировку от дублей. Завершённый поиск без найденных данных — не технический сбой. После перезагрузки страницы успешные группы читаются из БД. Пока другая вкладка владеет заданием, клиент ограниченно опрашивает эту группу. Смена автомобиля отменяет клиентские запросы и исключает отображение устаревшего ответа. Это работа запросами открытой страницы, не отдельный фоновый worker.

Ошибка сохраняется как безопасные `facts.failure.code/stage/message`, без ключей, персональных данных и сырого ответа провайдера. В журнал пишутся группа, категория сбоя, этап и длительность. Лимит 20 новых заданий в час теперь считается по группам; не повышался. Для проверки добавлен `scripts/test-mann-fluid-research-progress.mjs` (постепенная выдача, параллельность, частичный сбой, выборочный повтор и отмена).

Поиск запускается по выбранной модификации MANN: сервер загружает описание, двигатель, мощность и диапазон выпуска из `mann_filter_applications`. Данные карточки/VIN не подменяют выбранную модификацию. Для группы ключей запрашиваются общие данные; различия остаются неразрешёнными. Неизвестный ключ требует повторного выбора MANN.

Для каждой модификации проверяются все 12 категорий из `mann-fluid-systems.ts`: моторное масло, антифриз, тормозная жидкость, АКПП, МКПП, вариатор, робот, ГУР, раздатка, передний и задний редукторы, муфта полного привода. Отсутствие узла в каталоге больше не исключает его из поиска. В `facts.systems` сохраняется полный перечень с `present/absent/unknown`, причиной и источником, а в `facts.items` — найденные допуски/объёмы; `facts.unresolved` сохраняет оставшиеся вопросы. Уже при создании задания записываются все категории. Новая схема таблиц и миграция не нужны; старые записи не переписываются массово. Версия ключа кеша `selected_mann_all_systems_v3` запускает новый поиск при следующем подборе.

Отсутствующий агрегат (`absent`) требует ссылки из поисковых источников. Отсутствие данных само по себе означает `unknown`. Положительные данные каталога или поиска имеют приоритет над противоречащим заявлением об отсутствии узла. В интерфейсе всегда представлены все категории: незаполненные допуски и объёмы — прочерки, рядом причина/статус. Обычная проверка применяемости каталога не меняется.

Результаты сохраняются в существующую `ai_agent_technical_evidence`, factType `VIN_FLUID_RESEARCH_V1`, status `pending_review`, confidence 0. Исходные требования и связи MANN не изменяются. В интерфейсе это отдельные черновики со ссылками, не разрешение к применению или автоматическому подбору товара. Миграция не нужна. Запись помечается как черновик независимо от уверенности модели.

Для сохранения требуется URL из фактически возвращённых ссылок веб-поиска. Это проверяет происхождение ссылки, но не заменяет независимую проверку содержания, цитаты и применяемости. Непроверенные значения нельзя считать OEM-подтверждением.

Блокировка PostgreSQL защищает выдачу задания от параллельных запросов. Ограничение — 20 новых поисков в час на доступную организацию/филиал. Полностью заполненные результаты кешируются 30 дней, частичные и отсутствие данных — 6 часов, ошибка — 5 минут; незавершённое задание — 2 минуты. После истечения кеша следующий подбор повторяет поиск, фонового бесконечного поиска нет. Поиск не удерживает транзакцию. Полный VIN и персональные данные клиента в запрос не передаются.

Проверено локально: TypeScript, `test-mann-fluid-research.mjs` (модель/поиск/цитаты/кеш/изоляция/пропуски/ошибки/лимит/черновик), сериализация контекста MANN, Timeweb-only guards. Локальная страница запускается на 3001. Live-запрос OpenAI и реальное сохранение через рабочую БД не запускались; автоматические проверки используют моки. Публикация не выполнена. Перед публикацией требуется интеграционный прогон с PostgreSQL, проверка доступности модели с действующим ключом и визуальная проверка результата поиска.
