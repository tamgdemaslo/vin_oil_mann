# Дорожная карта: создание новой отгрузки

Дата выгрузки: 2026-05-26  
Маршрут экрана: `/shipment/new`  
Цель документа: передать в Figma полную карту текущего сценария, все поля формы, состояния и payload создания отгрузки.

## Источники в коде

- `src/app/shipment/new/NewShipmentPageClient.tsx` — основной экран и все видимые поля.
- `src/lib/demand-create-payload.ts` — итоговый payload создания отгрузки.
- `src/app/api/demands/route.ts` — backend-валидация и запись в локальная складская подсистема/локальную БД.
- `src/app/api/demands/metadata/route.ts` — загрузка дополнительных полей отгрузки.
- `src/lib/demand-attributes.ts` — обязательные дополнительные поля локальная складская подсистема.
- `src/app/api/local_inventory/counterparties/route.ts` — поиск/создание клиента.
- `src/app/api/local_inventory/products/route.ts` — поиск товаров и выдача остатков/ячеек.
- `src/types/lookup.ts` — структура VIN-подбора.
- `prisma/schema.prisma` — локальная модель отгрузки и позиций.

## Роли и входные условия

| Условие | Поведение |
|---|---|
| Пользователь не авторизован | Редирект на `/login?from=/shipment/new`. |
| Роль `admin` или `master`, смена не открыта | Редирект на открытие смены. |
| Роль `admin`, касса не открыта | Редирект на `/cash?needShift=1`. |
| Авторизация и смена есть | Загружаются организации, склады, дополнительные поля, клиентские и товарные справочники по мере ввода. |

## Карта сценария

1. Пользователь открывает `Операции -> Новая отгрузка`.
2. Система проверяет авторизацию, смену и кассу.
3. Система подгружает организации и склады. Организация выбирается первой из списка, склад — сначала с названием, содержащим `основной`, иначе первый.
4. Пользователь ищет существующего клиента или создает нового контрагента.
5. Пользователь вводит VIN.
6. Пользователь запускает подбор по VIN.
7. Система декодирует авто, показывает данные автомобиля, масло, фильтры, OEM и предложения ТО.
8. Если по VIN не найден двигатель, открывается модальное уточнение объема/мощности.
9. Пользователь добавляет масло/фильтры из VIN-подбора или вручную ищет товар в каталоге.
10. Пользователь редактирует позиции: количество, цену, скидку.
11. Пользователь проверяет дополнительные поля локальная складская подсистема, итог, комментарий и статус `Проведён`.
12. Пользователь сохраняет отгрузку.
13. Backend создает документ в локальная складская подсистема или локальной БД, затем экран переходит на `/shipment/{id}`.
14. Дополнительно пользователь может нажать `Произвести диагностику`: если отгрузка еще не создана, экран сначала создает черновик, затем открывает диагностический модал.

Важно для дизайна: кнопка сейчас называется `Сохранить и в предчек`, но фактически после успешного сохранения ведет на детальную отгрузку `/shipment/{id}`.

## Все поля: дополнительные поля локальная складская подсистема

Текущий экран показывает только редактируемые поля, имя которых после нормализации совпадает с одним из списка:

| Поле | State / payload | Автозаполнение |
|---|---|---|
| `vin номер` | `attributes[].value` | При вводе VIN. |
| `модель авто` | `attributes[].value` | Из VIN: `make + model`. |
| `год` | `attributes[].value` | Из VIN: `modelYear`. |
| `гос. номер` | `attributes[].value` | Ручной ввод. |
| `пробег` | `attributes[].value` | Ручной ввод. |
| `объем` | `attributes[].value` | Из `oilInfo.fillVolumeLiters`, если поле пустое. |
| `моторное масло` | `attributes[].value` | Ручной ввод. |

Служебные нюансы:

- Backend гарантирует наличие доп. полей `Объем` и `Моторное масло` в локальная складская подсистема, если их еще нет.
- Backend автоматически добавляет доп. поле `Эко пользователь`, если такое поле есть в локальная складская подсистема. В UI оно не редактируется.
- В payload уходят только атрибуты с `meta.href` и непустым значением.

## Payload создания отгрузки

UI отправляет на `/api/demands`:

```json
{
  "organization": { "meta": "selectedOrg.meta" },
  "agent": { "meta": "selectedAgent.meta" },
  "store": { "meta": "selectedStore.meta" },
  "description": "description или undefined",
  "applicable": false,
  "moment": "YYYY-MM-DD HH:mm:ss",
  "attributes": [
    {
      "id": "attribute.id",
      "name": "attribute.name",
      "meta": "attribute.meta",
      "value": "attribute.value"
    }
  ],
  "positions": [
    {
      "quantity": 1,
      "price": 1000,
      "discount": 0,
      "assortment": { "meta": "position.assortmentMeta" }
    }
  ]
}
```

Backend преобразует в локальная складская подсистема:

| Поле | Правило |
|---|---|
| `organization`, `agent`, `store` | Обязательны, должны иметь `meta.href`. |
| `name` | Поддерживается backend, но текущий UI не задает. |
| `description` | Trim, отправляется если не пустой. |
| `moment` | Trim, отправляется если не пустой. |
| `applicable` | Boolean, отправляется всегда если boolean. |
| `attributes` | Только непустые значения и только с `meta.href`; формат `{ meta, value }`. |
| `positions[].quantity` | Number или `1`, если невалидно. |
| `positions[].price` | Рубли из UI умножаются на 100 и округляются. |
| `positions[].discount` | Number или `0`. |
| `positions[].vat` | Default `0`. |
| `positions[].vatEnabled` | Default `false`. |
| `Эко пользователь` | Автоматически добавляется backend, если доп. поле есть в локальная складская подсистема. |

| `brand` | `decoded.make` или первое слово из `модель авто`. |
| `model` | `decoded.model` или остаток строки `модель авто`. |

## Состояния для Figma

1. Пустая форма: загрузка справочников завершена, клиент не выбран, VIN пустой, позиций нет.
2. Проверка доступа: загрузка, редирект на login, редирект на смену/кассу.
3. Поиск клиента: ввод, загрузка, результаты, ничего не найдено.
4. Создание клиента: пустая форма, ошибка `Наименование`, loading, успешный выбор.
5. VIN пустой: кнопка подбора disabled.
6. VIN loading: кнопка `Подбор...`, место под результат.
7. VIN найден: авто, масло, фильтры, OEM, предложения ТО.
8. VIN найден, но двигатель не определен: модал объема/мощности.
9. VIN ошибка: `decodeError`, `localCatalogError`, нет найденных товаров.
10. Подбор без остатков: найденные позиции есть, но все `quantity=0`.
11. Много вариантов масел: карточки масла, фильтры, no-stock details.
12. Ручной поиск товара: пустой, loading, результаты, нет результатов.
13. Позиции пустые: секция таблицы не показана.
14. Позиции добавлены: широкая таблица с редактированием количества, цены, скидки.
15. Итоги: черновик, проведенная отгрузка, комментарий, ошибка сохранения, loading save.
16. Диагностика: кнопка disabled/enabled, создание черновика перед открытием, открытый modal.
17. После сохранения: переход на детальную отгрузку.

## Замечания для редизайна

- Организация и склад сейчас не выбираются явно на форме, а только отображаются в контексте. Для дизайна стоит решить, нужны ли полноценные селекты.
- Label VIN говорит `17 знаков`, но подбор разрешен от 8 символов. Лучше согласовать правило.
- Кнопка `Сохранить и в предчек` фактически ведет на детальную отгрузку, а не сразу на предчек.
- Кнопка общей скидки `изменить` визуально есть, но обработчика нет.
- Кнопки `Заказ-наряд` и `Под капот` на новой отгрузке disabled до появления `demandIdLocal` и сейчас без активного действия на этом экране.
- Таблица позиций широкая: для Figma нужен отдельный мобильный/узкий вариант или карточная раскладка.
- `Себестоимость` и `Маржа` зависят от `stock.cost`, который не всегда приходит при ручном добавлении товара.
